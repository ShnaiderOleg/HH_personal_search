## Выполнено: версионирование статических файлов

Статус: реализовано локально, ожидает коммита и push.

### Цель

Исключить использование устаревших CSS и JavaScript после ручного production-деплоя.

### Реализованное решение

К URL статических файлов добавлена управляемая версия:

```html
<link rel="stylesheet" href="/static/style.css?v=<version>">
<script src="/static/app.js?v=<version>" defer></script>
```

Настройка `STATIC_VERSION` задает версию вручную через `.env`. Если значение пустое, приложение автоматически рассчитывает воспроизводимый короткий SHA-256 по содержимому `style.css` и `app.js`. Поэтому URL меняется только при изменении этих файлов и не требует ручного обновления после каждого деплоя.

### Критерии готовности

- После обновления production браузер загружает новые CSS и JavaScript без ручной очистки кэша.
- Страницы `/`, `/searches` и `/vacancies` работают без ошибок.
- На ширине 320, 375, 390, 430 и 768 px отсутствует горизонтальное переполнение.
- Поля, чекбоксы, кнопки и длинный текст не накладываются друг на друга.
- Таблицы на мобильной ширине отображаются читаемыми карточками.
- Десктопная верстка не ухудшилась.
- Все автоматические тесты проходят.

### Обязательная проверка после реализации

```powershell

```

Дополнительно проверить локально:

- `http://127.0.0.1:8000/vacancies`;
- версионные URL `/static/style.css?v=<version>` и `/static/app.js?v=<version>`;
- фактическую загрузку новой версии статических файлов без старого кэша.

После проверок Codex должен показать результат и предложить коммит и push. Не коммитить и не отправлять изменения без явного согласия владельца.
